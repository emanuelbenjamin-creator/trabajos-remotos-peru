# Clase: JavaScript para automatización

Curso: WorkJob Clases, preparación para trabajos remotos desde Perú en automatización con IA. Semana 1 del plan.
Público: personas que saben usar n8n y quieren conseguir trabajo remoto en automatización, LLMs, RAG y agentes de IA. Tienen inglés básico.
Resumen: El lenguaje de los nodos Code de n8n y de casi toda la web. Lo justo para transformar datos sin depender de nodos hechos.

## Introducción

JavaScript es el lenguaje que corre en todos los navegadores y en Node.js, y es el que usa n8n en sus nodos Code y en sus expresiones. No necesitas ser desarrollador web: necesitas el JavaScript que sirve para limpiar, combinar y transformar datos.

En las ofertas, JavaScript o TypeScript aparece en casi una de cada cinco, y en una de cada cuatro de las que coinciden con tu perfil. Saberlo te permite resolver en 5 líneas lo que con nodos visuales toma 10 pasos, y es la puerta a TypeScript, React y Node.js si después quieres ir más allá.

Estas 8 sesiones van de lo básico a usarlo de verdad dentro de n8n, con ejercicios sobre datos reales.

## Objetivos

- Leer y escribir variables, condiciones, funciones y bucles.
- Manipular arrays y objetos con map, filter, reduce y desestructuración.
- Trabajar con textos y fechas sin errores de formato.
- Entender promesas y async/await para llamadas a APIs.
- Escribir nodos Code en n8n que transformen muchos items.
- Depurar errores con console.log y leyendo el mensaje de error.

## Sesión 1: Variables, tipos y operadores (45 minutos)

Una variable es una caja con nombre. En JavaScript moderno se crean con const (no se reasigna) y let (sí se reasigna); evita var, que es antiguo.

Los tipos básicos son texto ("hola"), número (42), booleano (true), null, undefined, objetos y arrays. JavaScript convierte tipos solo, y eso causa sorpresas: "5" + 1 da "51". Por eso compara siempre con ===, que no convierte.

Los textos con backticks permiten insertar variables: ` Hola ${nombre} `. Lo vas a usar todo el tiempo para armar mensajes y URLs.

Conceptos clave:
- const y let
- Tipos básicos
- === en lugar de ==
- Template strings con ${}

Ejercicio práctico: En la consola del navegador crea const nombre, let edad y arma con template string la frase «Ana tiene 30 años». Prueba "5" + 1 y "5" * 1 y explica el resultado.

Preguntas frecuentes:
- Pregunta: ¿Cuándo uso let en lugar de const?
  Respuesta: Solo cuando vas a cambiar el valor, por ejemplo un contador. Por defecto usa const.
- Pregunta: ¿Qué diferencia hay entre null y undefined?
  Respuesta: undefined significa que no se asignó nada; null es un vacío puesto a propósito. En datos de APIs verás ambos.
- Pregunta: ¿Por qué 0.1 + 0.2 no da exactamente 0.3?
  Respuesta: Por cómo se guardan los decimales en binario. Para dinero, redondea con toFixed(2) o trabaja en céntimos.

## Sesión 2: Condiciones y funciones (45 minutos)

Con if, else if y else decides qué camino seguir. Para elegir un valor en una línea existe el ternario: const tipo = monto > 1000 ? "grande" : "pequeño".

Una función agrupa pasos que repites. La forma moderna es la función flecha: const iva = (monto) => monto * 0.18. Recibe parámetros, hace algo y devuelve un resultado con return.

Dos operadores te salvarán de errores con datos incompletos: ?. lee un campo solo si existe (cliente?.email) y ?? pone un valor por defecto si algo es null o undefined (telefono ?? "sin teléfono").

Conceptos clave:
- if / else y ternario
- Funciones flecha
- return
- ?. y ?? para datos incompletos

Ejercicio práctico: Escribe una función clasificarLead(lead) que devuelva «caliente» si el presupuesto es mayor a 5000 y tiene email, «tibio» si solo tiene email y «frío» en otro caso. Pruébala con tres objetos.

Preguntas frecuentes:
- Pregunta: ¿Qué devuelve una función sin return?
  Respuesta: undefined. En una función flecha de una sola línea sin llaves, el return es implícito.
- Pregunta: ¿Qué pasa con cliente.direccion.ciudad si direccion no existe?
  Respuesta: Da error. Con cliente.direccion?.ciudad obtienes undefined sin romper el flujo.
- Pregunta: ¿Cuál es la diferencia entre || y ???
  Respuesta: || reemplaza cualquier valor falso (incluidos 0 y ""); ?? solo reemplaza null y undefined. Para números usa ??.

## Sesión 3: Arrays: map, filter y reduce (55 minutos)

Casi todo lo que transformas en automatización es una lista: filas, leads, productos, mensajes. Tres métodos resuelven el 90 % de los casos.

map transforma cada elemento y devuelve una lista del mismo tamaño: emails.map(e => e.toLowerCase()). filter se queda con los que cumplen una condición: leads.filter(l => l.pais === "Perú"). reduce resume la lista en un solo valor, como una suma: ventas.reduce((total, v) => total + v.monto, 0).

También conviene conocer find (el primero que cumple), some y every (¿alguno o todos cumplen?), sort y includes. Encadenarlos es elegante: filtrar, luego transformar, luego sumar.

Conceptos clave:
- map transforma
- filter selecciona
- reduce resume
- find, some, sort, includes

Ejercicio práctico: Con el array de /users de JSONPlaceholder: obtén solo los emails que terminan en .biz, en minúsculas, y cuenta cuántos usuarios viven en una ciudad que empieza con «S».

Preguntas frecuentes:
- Pregunta: ¿map modifica el array original?
  Respuesta: No, devuelve uno nuevo. sort sí modifica el original; para evitarlo usa [...lista].sort() o toSorted().
- Pregunta: ¿Qué devuelve filter si nadie cumple?
  Respuesta: Un array vacío [], no null. Revisa .length antes de usar el primer elemento.
- Pregunta: ¿Cómo ordeno por un número?
  Respuesta: lista.sort((a, b) => a.precio - b.precio) de menor a mayor; invierte la resta para mayor a menor.

## Sesión 4: Objetos, desestructuración y spread (45 minutos)

Un objeto agrupa datos con nombre: { nombre: "Ana", email: "ana@x.com" }. Lees con punto (lead.email) o con corchetes cuando el nombre está en una variable (lead[campo]).

La desestructuración saca campos en una línea: const { nombre, email } = lead. El operador spread copia y combina: { ...lead, estado: "contactado" } crea un objeto nuevo con todo lo de lead más el campo nuevo. Es la forma limpia de enriquecer datos en un flujo.

Object.keys, Object.values y Object.entries te permiten recorrer un objeto cuando no sabes qué campos trae, algo común con respuestas de APIs.

Conceptos clave:
- Punto y corchetes
- Desestructuración
- Spread ...
- Object.entries

Ejercicio práctico: Toma un usuario de JSONPlaceholder y crea un objeto nuevo solo con nombre, email y ciudad (que está dentro de address), más un campo fuente: "api".

Preguntas frecuentes:
- Pregunta: ¿Cómo renombro un campo al desestructurar?
  Respuesta: const { email: correo } = lead crea la variable correo con el valor de lead.email.
- Pregunta: ¿El spread copia también los objetos internos?
  Respuesta: No: hace una copia superficial. Los objetos anidados siguen compartidos. Para copia completa usa structuredClone(obj).
- Pregunta: ¿Cómo convierto un objeto en filas clave-valor?
  Respuesta: Object.entries(obj) devuelve [[clave, valor], ...], perfecto para recorrerlo con map.

## Sesión 5: Textos, fechas y expresiones regulares (50 minutos)

Limpiar textos es tarea diaria: trim() quita espacios, toLowerCase() normaliza, split(",") separa, replace reemplaza e includes busca.

Las fechas son traicioneras por las zonas horarias. new Date().toISOString() da la fecha en UTC, que es lo que esperan las APIs. Perú está en UTC−5. n8n incluye la librería Luxon: $now.setZone("America/Lima").toFormat("dd/LL/yyyy") resuelve la mayoría de casos.

Las expresiones regulares buscan patrones: un email, un teléfono, un RUC. No hace falta memorizarlas: escríbelas y pruébalas en regex101, o pídele una al LLM y verifícala allí.

Conceptos clave:
- trim, split, replace, includes
- UTC vs hora local
- Luxon en n8n ($now)
- Regex probadas en regex101

Ejercicio práctico: Dado un texto con varios correos y teléfonos mezclados, extrae todos los emails con una regex y conviértelos a minúsculas sin duplicados.

Preguntas frecuentes:
- Pregunta: ¿Por qué una fecha sale con un día de diferencia?
  Respuesta: Porque se interpretó en UTC y se mostró en hora local (o al revés). Define siempre la zona horaria al formatear.
- Pregunta: ¿Cómo quito duplicados de una lista?
  Respuesta: [...new Set(lista)].
- Pregunta: ¿Debo validar emails solo con regex?
  Respuesta: Sirve para filtrar formatos imposibles, pero no confirma que exista. Para eso hace falta enviar un correo o un servicio de verificación.

## Sesión 6: Asincronía: promesas y async/await (50 minutos)

Llamar a una API toma tiempo y JavaScript no se queda esperando: sigue con lo demás. Una promesa representa un resultado que llegará después.

Con async y await el código se lee de arriba abajo: const res = await fetch(url); const datos = await res.json();. Envuélvelo en try/catch para capturar errores de red o de la API.

Para varias llamadas independientes usa await Promise.all([...]): corren en paralelo y terminas antes. Pero cuidado con los límites de uso: 500 llamadas a la vez pueden darte un 429. En n8n, prefiere el nodo HTTP Request con Batching para eso.

Conceptos clave:
- Promesa
- async / await
- try / catch
- Promise.all y límites de uso

Ejercicio práctico: En Node.js, escribe una función async que traiga los usuarios 1, 2 y 3 de JSONPlaceholder en paralelo con Promise.all y muestre sus nombres. Luego provoca un error con una URL mala y captúralo.

Preguntas frecuentes:
- Pregunta: ¿Qué pasa si olvido await?
  Respuesta: Obtienes la promesa, no el dato. Verás Promise { <pending> } o campos undefined.
- Pregunta: Si una de las promesas de Promise.all falla, ¿qué ocurre?
  Respuesta: Todo falla. Si quieres seguir con las que sí funcionaron, usa Promise.allSettled.
- Pregunta: ¿fetch lanza error con un 404?
  Respuesta: No. Solo falla por problemas de red. Revisa res.ok o res.status para detectar 4xx y 5xx.

## Sesión 7: El nodo Code de n8n (55 minutos)

El nodo Code ejecuta tu JavaScript sobre los items del flujo. Tiene dos modos: «Run Once for All Items», donde recibes todos con $input.all() y devuelves un array; y «Run Once for Each Item», donde trabajas con $json del item actual.

Lo que devuelves debe tener la forma de n8n: una lista de objetos { json: {...} }. Ese es el error número uno al empezar.

Desde el código también puedes leer otros nodos ($('Nombre del nodo').all()), usar Luxon para fechas y hacer console.log para ver valores en la consola del navegador. Úsalo cuando necesites lógica que con nodos visuales quedaría enredada.

Conceptos clave:
- Modo todos los items vs cada item
- $input.all() y $json
- Devolver [{ json: {...} }]
- $('Nodo') para leer otros nodos

Ejercicio práctico: Recibe 10 leads desde un nodo anterior, y en un solo nodo Code normaliza emails, quita duplicados, calcula la clasificación caliente/tibio/frío y devuelve solo los calientes.

Preguntas frecuentes:
- Pregunta: Mi nodo Code da error de formato al devolver un array simple. ¿Por qué?
  Respuesta: n8n espera objetos con la clave json. Devuelve lista.map(x => ({ json: x })).
- Pregunta: ¿Cuándo prefiero el nodo Code sobre nodos visuales?
  Respuesta: Cuando la transformación tiene varias condiciones, cálculos o recorridos. Si es un solo cambio de campo, un nodo Set es más claro para quien lo mantenga.
- Pregunta: ¿Puedo usar librerías externas?
  Respuesta: En n8n autoalojado se pueden permitir algunos módulos con variables de entorno; en la nube hay limitaciones. Lo básico (Luxon, crypto) ya viene incluido.

## Sesión 8: Depurar y siguiente paso: TypeScript (40 minutos)

Depurar es leer el mensaje de error con calma: dice qué pasó y en qué línea. Cannot read properties of undefined (reading 'email') significa que el objeto antes de .email no existe. Pon console.log antes de la línea, mira el dato real y corrige.

Un LLM es excelente para explicarte un error: pega el código, el mensaje y un ejemplo del dato. Pero entiende la solución antes de copiarla.

TypeScript es JavaScript con tipos: declaras que email es un texto y el editor te avisa antes de ejecutar. Aparece junto a JavaScript en muchas ofertas. Cuando domines lo de este tema, un curso corto de TypeScript es el siguiente paso natural.

Conceptos clave:
- Leer el mensaje de error
- console.log del dato real
- Usar el LLM para entender, no solo copiar
- TypeScript = JavaScript con tipos

Ejercicio práctico: Toma tu nodo Code de la sesión anterior, rómpelo a propósito de tres formas distintas (campo inexistente, falta await, formato de salida) y anota el mensaje de cada error y cómo lo arreglaste.

Preguntas frecuentes:
- Pregunta: ¿Qué significa is not a function?
  Respuesta: Que intentas llamar como función algo que no lo es, por ejemplo .map sobre un objeto en vez de un array.
- Pregunta: ¿Necesito TypeScript para trabajar en automatización?
  Respuesta: No para empezar. Sí suma en puestos de desarrollo o si creas nodos propios para n8n, que se escriben en TypeScript.
- Pregunta: ¿Cómo pido ayuda bien a un LLM con un error?
  Respuesta: Da el código, el error completo, un ejemplo del dato de entrada y lo que esperabas obtener. Pide que explique la causa, no solo el arreglo.
